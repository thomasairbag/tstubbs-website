# CLAUDE.md: tstubbs.net website

## Purpose

tstubbs.net is the personal academic and policy website of Professor Thomas Stubbs (Royal Holloway, University of London). This repository rebuilds it, formerly on Owlstown, as a static Quarto website served free from GitHub Pages, with publications drawn from the "My Publications" list of Thomas's Zotero library so that a publication is edited in one place only. The content model is kentikelenis.net; the emphasis is policy and advisory work alongside the academic record.

## Working rules (carried over from the IMF Monitor site, which Thomas approved)

- British English with Oxford commas; publication titles exactly as published. Concise prose, no marketing language.
- Never invent facts, links, DOIs, dates, citations, or file names. Every published fact traces to Zotero, the CV, Thomas, or a named source.
- Read the relevant section of `_private/WEBSITE_AUDIT_PLAN.md` before working on a page, the data pipeline, or a deployment step. Record each decision in its Section 9 log. Open decisions are not settled: ask rather than anticipate them.
- Don't redesign the site or change an approved decision without asking Thomas. If the plan looks wrong, raise it.
- Work one stage at a time; after each, report what changed, what was tested, and what Thomas needs to do next.
- The repository will be public. Confidential material (the plan, the audit, correspondence) lives only in `_private/`, which Git ignores. `CLAUDE.local.md` holds this machine's paths and is not committed either.

## Technical stack (plan Section 7)

- Quarto website edited and previewed in RStudio on Windows (`tstubbs-website.Rproj`); R 4.3.3; Quarto 1.9.38 ships with RStudio and is not on PATH (path in `CLAUDE.local.md`). `quarto render` writes the site to `docs/`, which GitHub Pages serves from `main`; only `.qmd` files are rendered, and `files/` and `fonts/` are copied as resources.
- Site set-up (Stage 3): `_quarto.yml` holds the menu (decision 1, amended), footer, Google Analytics (decision 10), the staging `site-url` and a `noindex` tag (both change at cutover, plan Stage 7), and no search box. `styles/custom.scss` holds the palette and type (decision 19) and one column for the menu bar, page, and footer: 1,100px including 24px padding (16px below 720px), with Quarto's page grid switched off. Don't use `page-layout: custom` for this: it drops the `<main>` element the skip link needs. `styles/fonts.css` declares the self-hosted fonts in `fonts/` (Google Fonts' own WOFF2 files, Latin and extended Latin, with their OFL licences). `_includes/` holds the page-title partial ("Academic Writing | Thomas Stubbs") and the skip link, both from IMF Monitor. `R/make-favicon.R` draws `images/favicon.png`. The menu fits on one line from 992px with 15px to spare; recheck that whenever a menu label or the icons change.
- Publications: `R/refresh-publications.R` reads the public Zotero API for user 9618525 (no API key; My Publications is public) and writes `data/publications.json`, which is committed. It copies each item's attached PDF from the Zotero library on this computer (read from a temporary copy of the database) to `files/publications/<key>.pdf`; which items get one is set by `pdf_sections` and `pdf_open_books` in the script (decision 7). Pages render lists from it through helpers in `R/publications.R`. Section placement comes from the Zotero item type, overridden by `site:` tags; replication-data links, awards, and "Cited in" entries come from `site-data:`, `site-award:`, and `site-cited:` lines in the item's Extra field. No featured items or blurbs. No research-theme tags, badges, or filters (decision 14). Zotero publishes Extra but not tags for My Publications, so the script asks once per `site:` tag; citations use `style=apa` with `locale=en-US` (en-GB breaks APA's "(Eds.)"). Never type a citation into a page.
- Other facts live in `data/site.yml` (profile, contact, expertise) and `data/policy-projects.yml`.
- The CV is one PDF at `files/cv/Thomas_Stubbs_CV.pdf`. The refresh script copies it from Thomas's Dropbox whenever his PDF there is newer and different (decision 21), so updating the CV is: save the PDF in Dropbox, run the script, render, push.
- No backend, database, CMS, JavaScript framework, or paid service. Publishing by a committed `docs/` folder rendered in RStudio, not a CI pipeline (decision 15, 10 November); repository `thomasairbag/tstubbs-website`, public (decision 16). Fraunces for headings, IBM Plex Sans for text, oxblood `#7B2D26` accent (decision 19). Quarto's Bootstrap theme with modest SCSS; Bootstrap Icons.
